블로그를 하나 만들어 보기로 했다. 처음부터 복잡한 기능을 넣기보다, 글을 쓰고 공개할 수 있는 기본 구조를 만들면서 GitHub Pages와 Jekyll을 차근차근 익혀 보기로 했다.

## 1. GitHub 계정과 Pages 저장소 만들기

먼저 GitHub 계정을 만들고 `dksworld1.github.io`라는 저장소를 준비했다. GitHub Pages는 저장소에 있는 웹 파일을 공개 웹사이트로 제공해 주는 기능이다. 그래서 별도의 웹 서버를 직접 운영하지 않아도 저장소의 내용을 사이트로 보여줄 수 있다.

사용자 사이트는 저장소 이름을 `계정이름.github.io` 형식으로 만든다. 이 블로그의 주소도 저장소 이름을 따라 [dksworld1.github.io](https://dksworld1.github.io/)가 됐다. Jekyll을 사용하면 Markdown으로 쓴 페이지와 글을 HTML로 만들어 Pages에 올릴 수 있다.

## 2. 저장소를 내려받고 첫 화면 바꾸기

저장소를 로컬 컴퓨터에 복제한 뒤 기본 파일부터 살펴봤다. 사이트 제목과 설명, 첫 화면 인사말, 소개 페이지를 내 블로그에 맞게 손보고 다시 GitHub에 올렸다.

이 과정을 통해 로컬 파일을 수정하고, Git으로 변경 사항을 저장한 뒤, 원격 저장소에 보내면 공개 페이지에 반영되는 흐름을 확인했다. 우선 작은 수정만 배포해 보니 사이트를 만드는 전체 과정을 이해하기 쉬웠다.

## 3. Jekyll과 Minima 테마 적용하기

다음으로 Jekyll의 `minima` 테마를 적용했다. 테마는 페이지의 기본 레이아웃과 스타일을 제공해서, 글 쓰기에 집중하면서도 사이트의 모양을 빠르게 갖출 수 있게 해 준다.

로컬 빌드를 하면서 필요한 Ruby gem이 빠져 있으면 빌드가 멈춘다는 점도 배웠다. 이 블로그에서는 시간대 처리를 위한 `tzinfo`와 설정에 지정된 `minima` 테마가 필요했다. 필요한 의존성을 설치한 뒤 빌드가 성공했고, 테마의 기본 구성을 바탕으로 화면을 더 다듬을 수 있었다.

테마를 그대로 쓰는 데서 그치지 않고, 최근 글과 카테고리를 쉽게 찾을 수 있도록 모던 대시보드 형태를 골랐다. 왼쪽에는 카테고리 메뉴를 두고, 화면에는 최근 글을 보여 주는 방향이다. 글에 카테고리를 지정하면 메뉴와 전체 글 보관 페이지에도 자동으로 나타나도록 구성했다.

## 지금까지 해본 것

- GitHub Pages용 사용자 저장소를 만들고 사이트 주소를 확인했다.
- 저장소를 로컬에 복제해 기본 화면을 수정하고 배포했다.
- Jekyll과 Minima 테마를 적용하고, 카테고리 패널이 있는 화면으로 꾸몄다.

이제 기본 틀이 생겼으니, 앞으로는 배우고 직접 해 본 내용을 한 편씩 기록해 보려 한다.
